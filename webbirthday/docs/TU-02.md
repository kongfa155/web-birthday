# TU-02 — Đăng nhập bằng Google

Phạm vi được duyệt: lần đầu tạo tài khoản USER riêng; các lần sau đăng nhập đúng
tài khoản đó bằng Google `sub`. Không tự liên kết/gộp vào bất kỳ tài khoản cũ nào,
kể cả khi email hoặc username trùng. Không có chức năng liên kết/hủy liên kết tài khoản.

## Cấu hình và luồng

Backend dùng Node.js 22 trở lên và `google-auth-library` chính thức. Frontend tải
Google Identity Services từ `https://accounts.google.com/gsi/client`, dùng nút do Google
render, popup/callback, không dùng One Tap hoặc tự chọn tài khoản.

Thêm vào file `.env` hiện có, không thay thế các cấu hình khác:

```dotenv
# webbirthday/.env — cùng OAuth Web Client ID với backend
VITE_GOOGLE_CLIENT_ID=YOUR_CLIENT_ID.apps.googleusercontent.com

# webbirthday/backend/.env
GOOGLE_CLIENT_ID=YOUR_CLIENT_ID.apps.googleusercontent.com
# Origin frontend được phép; mặc định gồm cả địa chỉ loopback 127.0.0.1.
GOOGLE_AUTH_ORIGINS=http://localhost:5173,http://localhost,http://127.0.0.1:5173
```

Client ID là cấu hình công khai, không phải Client Secret. Không cần Client Secret,
Google access token, refresh token, Gmail API hay Drive API cho luồng này. Khi đổi env
phải khởi động lại Vite/backend. Backend chỉ trả JWT ứng dụng sau khi xác minh Google.

Google Cloud Console cần OAuth client loại Web application, Branding/Audience phù hợp
và Authorized JavaScript origins khớp URL thật. Local: `http://localhost`,
`http://localhost:5173` và `http://127.0.0.1:5173`; production: origin HTTPS thật và
`GOOGLE_AUTH_ORIGINS` tương ứng. Hai hostname localhost/127.0.0.1 là hai origin riêng,
cần thêm từng origin trên Google Console; phiên đăng nhập trong trình duyệt không tự chia sẻ.
Không cần redirect URI cho popup/callback đang dùng. Nếu Console đang ở chế độ thử
nghiệm và yêu cầu test users, thêm tài khoản dùng để nghiệm thu trong Console.

Vite được cố định `port: 5173`, `strictPort: true` để không tự nhảy sang 5174 khi
có một phiên dev khác đang chạy. Mở `http://localhost:5173` hoặc
`http://127.0.0.1:5173`; origin khác cổng cần cấu hình tương ứng ở cả Google Console/backend.
Nếu thấy lỗi nguồn yêu cầu không được phép, kiểm tra URL đang mở trước khi thay đổi
danh sách origin. Nếu cổng 5173 đã có server dự án, dùng lại phiên đó hoặc dừng nó
trước khi chạy `npm run dev` lần nữa.

Đã bổ sung backend cho `http://127.0.0.1:5173` và kiểm tra challenge thực tế trả
`200` ở cả localhost/127.0.0.1, cổng 5174 vẫn bị từ chối. Kiểm tra trình duyệt
ngày 27/11/2026 cho thấy Google còn báo `The given origin is not allowed for the
given client ID` đối với 127.0.0.1. Chủ OAuth client cần thêm chính xác
`http://127.0.0.1:5173` vào Authorized JavaScript origins trên Google Cloud rồi Save;
cấu hình backend không tự thay đổi danh sách origin trên Google.

1. Frontend tải SDK rồi gọi `POST /api/users/google/challenge` cùng cookie trình duyệt.
2. Backend tạo nonce ngẫu nhiên, trả `{ nonce, expiresIn: 300 }` và cookie HttpOnly,
   SameSite=Lax, Secure khi `NODE_ENV=production`.
3. Frontend đưa nonce vào cấu hình Google. Callback nhận ID token và gửi
   `POST /api/users/google` với `{ credential }`, kèm cookie (`withCredentials: true`).
4. Backend xác minh chữ ký Google, audience/issuer/expiry/subject; so nonce trong token
   với challenge của trình duyệt và tiêu thụ challenge một lần.
5. Tìm theo `googleSub` duy nhất; có thì đăng nhập, chưa có thì tạo USER không mật khẩu.
6. Trả `{ token, user }` (`200` tài khoản cũ Google, `201` tài khoản mới), dùng lại
   AuthContext TU-01 và chuyển `/cards`.

Không bao giờ tra email để chọn/gộp tài khoản. Username mới do server sinh ngẫu nhiên.
Email chỉ lưu khi token có `email_verified: true`; không làm khóa định danh, không unique.
Tài khoản bị khóa trả `403 ACCOUNT_DISABLED` và không được tạo lại. Token sai, nonce
thiếu/sai/hết hạn/dùng lại nhận `401`; thiếu cấu hình/index hoặc Google gặp lỗi dịch vụ
nhận `503`; dữ liệu sai `400`, quá tần suất `429`.

Google endpoints chỉ chấp nhận Origin được cho phép; CORS credential dùng danh sách
origin cụ thể, không wildcard. Không ghi Google credential hoặc JWT vào log/database.
Cookie nonce chỉ phục vụ đăng nhập, không thay cơ chế Bearer token của API ứng dụng.

## Thay đổi dữ liệu đã duyệt

- `users.googleSub`: string tùy chọn, 1–255 ký tự; chỉ nhận từ token đã xác minh.
- `users.email`: string tùy chọn, tối đa 320 ký tự; thông tin Google đã xác minh.
- `password`: bắt buộc khi không có `googleSub`; Google-only không lưu password/hash giả.
- Giữ `username` và index `username_1` như TU-01.
- Thêm index `googleSub_unique`: `{ googleSub: 1 }`, `unique: true`,
  `partialFilterExpression: { googleSub: { $type: "string" } }`, collation simple.
- Không thêm `authProvider`, ảnh đại diện hoặc trường khác; không backfill tài khoản cũ.
- `autoIndex`/`autoCreate` vẫn tắt; không dùng `syncIndexes()` khi chạy ứng dụng.

Index đã được tạo theo phê duyệt ngày 27/11/2026. Trước/sau thay đổi có 1 tài khoản;
fingerprint toàn bộ dữ liệu tài khoản không đổi. Giữ nguyên `_id_`, `username_1`.
Snapshot index và kết quả đối chiếu, không chứa thông tin xác thực:
`/home/nghhuan2005/.cache/webbirthday-tu02-index-gXjnZw/report.json`.

Đăng ký username/password công khai vẫn chỉ nhận username/password, không nhận các
trường Google do client tự khai. Đăng nhập mật khẩu vào tài khoản Google-only trả lỗi
thông tin đăng nhập chung, không phát sinh lỗi bcrypt/server.

## Kiểm thử và vận hành

```bash
cd webbirthday/backend
npm install
npm test

cd ..
npm run build
npm run lint
```

Các test Google dùng cặp khóa RSA và chứng thư giả lập qua biên mạng của thư viện
Google, vẫn chạy xác minh chữ ký/audience/issuer/expiry thật. Model được giả lập;
không tạo tài khoản Google giả trên Atlas. Bộ hồi quy TU-01 vẫn chạy cùng.
Kiểm tra API trên Atlas: index sẵn sàng, challenge trả cookie HttpOnly, credential
không hợp lệ bị từ chối; số lượng tài khoản không đổi.

Kết quả kiểm tra triển khai:

- 34 kiểm thử backend thành công (15 Google và 19 hồi quy TU-01).
- 5 nhóm kiểm tra React DOM Google thành công với SDK/API giả lập: lỗi tải và thử
  lại; StrictMode/gửi lặp/auto-login; tài khoản khóa và nonce mới; chuyển trang và
  callback cũ; phản hồi đến sau khi rời trang. 8 nhóm kiểm tra UI TU-01 vẫn thành công.
- Build và lint tập trung trên các file thay đổi thành công.
- Trên trình duyệt thật, SDK render nút Google và mở trang Google đăng nhập vào ứng
  dụng `HappyBirthday` tại origin localhost:5173. Chưa nhập thông tin tài khoản Google;
  cần người dùng hoàn tất xác thực để nghiệm thu phiên Google thật.

Nonce store và rate limiter hiện trong bộ nhớ một tiến trình. Nếu triển khai nhiều
instance cần store dùng chung hoặc thiết kế phiên đăng nhập phù hợp; restart backend
sẽ vô hiệu challenge đang chờ và người dùng phải chọn Google lại. Challenge có thời
hạn 5 phút; frontend cho phép thử lại để lấy nonce mới. Không dựa vào Google logout
để thu hồi JWT ứng dụng; đăng xuất dùng luồng TU-01.

Để nghiệm thu Google thật, người dùng chọn tài khoản Google trên trình duyệt. Không
thể kết luận thành công chỉ từ Client ID hoặc token mô phỏng. Lượt đăng nhập thật có
thể tạo USER mới theo đúng phạm vi đã duyệt; không tự xóa tài khoản thật sau nghiệm thu.

## Hoàn tác

Tắt nút/API Google nếu cần. Giữ tài khoản Google đã tạo, index và model tương thích
để không mất quyền sở hữu thiệp. Không quay về validator bắt buộc password trên mọi
tài khoản khi còn Google-only users. Không tự gán mật khẩu hoặc gộp email để khắc phục.
Nếu quyết định bỏ riêng index đã duyệt thì drop đúng `users.googleSub_unique`, giữ
nguyên các index khác; thao tác ngoài phạm vi phê duyệt cần đề xuất riêng.
