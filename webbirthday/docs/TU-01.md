# TU-01 — Đăng ký công khai và nền tảng phân quyền

Yêu cầu ngày 26/11/2026. Triển khai theo hướng bảo trì mã hiện có.

## Phạm vi

- Người dùng đăng ký bằng tên đăng nhập và mật khẩu, tự đăng nhập sau khi tạo tài khoản, chuyển tới `/cards`.
- Tên đăng nhập phân biệt hoa/thường, bỏ khoảng trắng đầu/cuối, dài 1–64 ký tự JavaScript. Không đổi tên tài khoản cũ trong database.
- Mật khẩu đăng ký có ít nhất 6 ký tự Unicode và tối đa 72 byte UTF-8 (giới hạn bcrypt). Không trim mật khẩu. Đăng nhập không áp đặt lại độ dài tối thiểu lên tài khoản cũ.
- Tài khoản đăng ký luôn là USER đang hoạt động, không nhận quyền hoặc danh sách thiệp từ request.
- JWT có thời hạn 1 ngày. Mỗi request cần quyền đều kiểm tra chữ ký, tài khoản hiện tại, trạng thái và vai trò trong database.
- Client xác nhận phiên qua `/api/users/me`, không tin `isAdmin` lưu trong trình duyệt.

## API

| API | Quyền và phản hồi |
| --- | --- |
| `POST /api/users/register` | Công khai; nhận `username`, `password`; `201` trả `token`, `user` an toàn |
| `POST /api/users/login` | Công khai; tài khoản bị khóa nhận `403 ACCOUNT_DISABLED` |
| `GET /api/users/me` | Phiên hợp lệ; trả `{ user }` |
| `POST /api/users` | Admin; tạo tài khoản qua chức năng quản trị hiện có |
| `GET /api/users`, `GET /api/users/:id` | Admin; thông tin tài khoản và `cardCount`, không nội dung/URL thiệp hoặc password hash |
| `PUT /api/users/:id` | Admin; chỉ nhận boolean `isActive`; không tự vô hiệu hóa mình |
| `GET /api/cards`, `GET /api/cards/:id` | User chỉ xem thiệp của mình đã hoàn chỉnh; Admin chỉ xem thiệp của mình hoặc thiệp cũ chưa có chủ |
| `POST /api/cards`, `PUT /api/cards/:id` | Admin; không được sửa thiệp riêng của người khác hoặc chuyển chủ sở hữu |
| `GET /api/templates`, `GET /api/templates/:id` | Người đã đăng nhập; dùng mẫu là bước tiếp theo |
| `POST /api/templates`, `PUT /api/templates/:id` | Admin |
| `POST /api/upload-base64` | Người đã đăng nhập; chỉ ảnh base64 PNG/JPEG/WebP/GIF, tối đa 5 MB |

`cardCount` đếm bản ghi thiệp của tài khoản, không phải tổng số ảnh hoặc file trên Cloudinary.
Drawer quản trị không còn gán/gỡ thiệp hoặc liệt kê nội dung của người dùng.
Chức năng User tự tạo thiệp, nhân bản mẫu và gửi/thu hồi thiệp là các hạng mục tiếp theo,
chưa được bổ sung trong TU-01.

Lỗi: `400` dữ liệu sai, `401` phiên sai/hết hạn, `403` thiếu quyền/tài khoản khóa,
`404` tài nguyên không tồn tại hoặc không thuộc phạm vi truy cập, `409` tên trùng,
`413` dữ liệu quá lớn, `429` quá tần suất, `503` dịch vụ/điều kiện đăng ký chưa sẵn sàng.
Không trả lỗi database hoặc stack trace cho trình duyệt.

## Database và vận hành

- Giữ nguyên model, migration, cấu trúc collection và dữ liệu cũ. Riêng index cũ
  `users.userID_1` đã được xóa sau khi người dùng phê duyệt cụ thể ngày 27/11/2026;
  `_id_` và unique index `username_1` được giữ nguyên.
- Server tắt `autoIndex`/`autoCreate` để không tự sửa database khi khởi động.
- Trước khi tạo tài khoản, server chỉ đọc index để xác nhận unique index đầy đủ,
  phân biệt hoa/thường trên `username`. Nếu thiếu hoặc không đọc được, không tạo tài khoản.
- Nếu cần tạo/sửa index phải có đề xuất và phê duyệt riêng. Không dùng `syncIndexes()`.
- Lỗi xác thực Atlas trước đó đã được khắc phục bằng cấu hình `.env` do người dùng cập nhật.
  Đã kiểm tra trực tiếp: unique index `username_1` hợp lệ, phân biệt hoa/thường.
- Bộ kiểm thử `npm test` không ghi database hoặc upload thật. Lượt nghiệm thu Atlas
  riêng đã tạo 3 tài khoản thử được phê duyệt, kiểm tra rồi xóa đúng cả 3 tài khoản;
  không có thay đổi Cloudinary hoặc bản ghi thiệp/mẫu.

Giới hạn theo IP: đăng ký 5 lần/giờ, đăng nhập 20 lần/15 phút, upload 30 lần/phút.
Limiter nằm trong bộ nhớ một tiến trình; cần kho dùng chung nếu chạy nhiều instance.
Nếu triển khai sau reverse proxy, phải cấu hình danh sách proxy tin cậy theo hạ tầng;
không tin tùy ý header `X-Forwarded-For` do client gửi.

Frontend mặc định gọi API cùng origin qua Vite proxy; khi triển khai riêng có thể đặt
`VITE_API_URL` trỏ tới backend. Giữ `JWT_SECRET` chỉ ở backend.

## Kiểm thử và giới hạn phát hành

```bash
cd webbirthday/backend
npm test

cd ..
npm run build
npm run lint
```

Backend test chạy HTTP thật tới Express với model và Cloudinary được giả lập,
không kết nối MongoDB. Bao gồm trùng tên đồng thời, cưỡng ép vai trò, token,
khóa tài khoản, quyền sở hữu, dữ liệu quản trị, validation và rate limit.

Kết quả triển khai: 19 kiểm thử backend thành công; build thành công. Kiểm tra
React DOM với API giả lập đã qua 8 nhóm tình huống: form và validation; đăng ký/
tự đăng nhập/đăng xuất; trùng tên/rate limit; đăng nhập cũ; cache giả quyền;
token hết hạn; request cũ không ghi đè phiên mới; drawer chỉ hiển thị thống kê.
Đã kiểm tra trực tiếp form đăng ký, báo thiếu dữ liệu và liên kết đăng nhập trên
trình duyệt. Ngày 27/11/2026 đã qua 22 kiểm tra tích hợp API với Atlas thật:
đăng ký và tự đăng nhập, mật khẩu bcrypt, cưỡng ép quyền Admin bị bỏ qua, trùng tên
đồng thời chỉ lưu một tài khoản, quản trị chỉ nhận metadata/count, chặn truy cập
trái quyền, token hết hạn, khóa/mở tài khoản và vô hiệu hóa token của tài khoản khóa.
Sau khi dọn, không còn tài khoản thử; tổng tài khoản trở về 0 như trước kiểm tra.
Đây là kiểm tra API với database thật; kiểm tra thao tác giao diện tự động phía trên
vẫn dùng API giả lập, không phải toàn bộ luồng trình duyệt với Atlas thật.
Lint toàn dự án còn 20 lỗi cũ ở editor/Tailwind; phần thay đổi TU-01 và backend

File Cloudinary hiện có vẫn được lưu theo URL công khai. Không có thay đổi remote
